# PI-level combined experiment: does Delta-Mask + Attention fix what persistence-checking couldn't?

Branch: `pi-level-idea`. This directory is the first joint artifact combining the
one-shot attribute-binding metric (metric A, `ssa/coig_ssa_colab.ipynb`) and the
Delta-Mask + Attention-IoU chain metric (metric B, `pilot/spatial_semantic_alignment.py`),
per the combined-arc plan in `CLAUDE.md`.

## What this answers

Track 1's Causal Relevance pilot (`pilot/`) found that CoIG's compositional lock defeats a
*persistence*-based faithfulness check: `persists_to_final` was 0.83 for both the **real**
condition and the **shuffled** (wrong-step) condition -- identical, because the lock keeps
every attribute in the final image regardless of which step it was actually supposed to
appear at. That's the motivating problem for all of Track 2.

Metric B's Delta-Mask design (`Delta = Current AND NOT Previous`) is supposed to be immune
to exactly this confound *by construction*. Before this experiment, that claim had only
been checked against 9 hand-built synthetic scenarios (`pilot/spatial_semantic_alignment.py`'s
`test_metric()`) -- never against real diffusion-generated images with real captured
attention. This experiment is that first real test, and it replicates Track 1's own
Real / Shuffled / Substituted design so the result is directly comparable to the 0.83-vs-0.83
finding it's meant to fix.

## Why SD1.5, not the actual CoIG/Gemini chains

CoIG's real chains (`coig/create_images/multi_step_out/`) were generated by Gemini 2.5
Flash Image through Google's API -- a closed model. Metric B needs to hook cross-attention
inside the generating UNet; that's impossible against a closed API. So this experiment
builds new, analogous locked chains with SD1.5 (open, hookable). This validates the
*mechanism*, not CoIG's own exact pixels -- see the module docstring in
`run_chain_experiment.py` for the full disclosure.

## Design

9 chains, one per `MECHANISM_PROMPTS` spec (already validated in metric A -- SD1.5 reliably
renders the right number of Mask-R-CNN-detectable people for these prompts, n=2/3/4
subjects). Each chain: a base image with no attributes, then one attribute-introduction
step per attribute, each masked to its subject's bounding box.

The lock is enforced with a RePaint-style per-step latent blend on the plain SD1.5 txt2img
UNet, not a dedicated inpainting checkpoint: every community SD1.5-inpainting mirror
(runwayml, botp, the stable-diffusion-v1-5 org's own copy) only ships pickle-format `.bin`
weights, and the pinned `torch==2.5.1` (required for T4/P100 dual-arch support) is blocked
by transformers' `torch.load` security gate from loading them (needs torch>=2.6, which
risks re-breaking P100/sm_60 support). The RePaint blend needs no second checkpoint: at
every denoising step, the region outside the subject's mask is forced to match the
correctly-noised original image at that noise level, so by the final step it's exactly the
original pixels -- including attributes added at earlier steps -- and only the masked
region is newly generated.

For each attribute's real captured cross-attention map (early denoising window, steps
0-50%), four conditions vary only the **delta-mask target** it's compared against:

| Condition | Delta-mask target | Prediction |
|---|---|---|
| `real` | the attribute, at its true introduction step | high IoU |
| `shuffled` | the same attribute, at a *different* step in the same chain | ~0 (locked in either direction) |
| `substituted` | an attribute from a *different* chain, never rendered here | ~0 (never segmented as present) |
| `attention_scrambled` | real delta target, but a *different* attribute's attention map | should drop vs. `real` if attention content matters, not just delta-mask size |

`attention_scrambled` ports metric A's Tier-1 falsification test #1 (attention
randomization) into the chain setting -- it's the check that the `real` condition's score
isn't just "delta mask is nonzero" but actually reflects attention content.

## Files

- `run_chain_experiment.py` -- the experiment. Self-contained (inlines a fixed copy of
  `SpatialSemanticAlignment` from `pilot/spatial_semantic_alignment.py`) so it can be
  pushed to Kaggle as a single script kernel. Bootstraps pinned `torch==2.5.1` +
  `torchvision==0.20.1` (cu121, dual T4/P100 support) and `diffusers>=0.31` when running
  on Kaggle (`KAGGLE_KERNEL_RUN_TYPE` env var), matching this project's existing Kaggle-GPU
  playbook.
- `kernel-metadata.json` -- Kaggle kernel config (`anonymous/coig-pi-level-chain-experiment`,
  GPU + internet enabled).
- `analyze_results.py` -- run locally after pulling `chain_experiment_results.csv` back
  from Kaggle. Prints per-condition summary stats and effect sizes, and states the
  pre-registered pass/fail explicitly rather than leaving it to eyeballing a table.

## Honest scope notes

- Subject-attribute inpainting masks use the full padded person bounding box, not a
  finer per-region (torso/head/hands) mask -- each subject only carries one attribute
  per chain in `MECHANISM_PROMPTS`, so this is sufficient here but wouldn't be for a
  prompt giving one subject multiple attributes in different regions.
- `attn_scrambled`'s attention swap draws from another attribute in the *same* chain,
  not a fully independent distribution -- a stronger version would also test attention
  from an unrelated chain entirely.
- DiT/FLUX/SD3 architectures are explicitly out of scope (see the module docstring in
  `pilot/spatial_semantic_alignment.py`); this experiment, like the rest of the combined
  arc so far, only claims UNet (SD1.5/SDXL) coverage.
