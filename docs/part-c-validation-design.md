# Design: Validating the Money Result (Part C)

Date: 2026-07-23. Branch: `pi-level-idea`. Author: Chayan (with Claude).

Companion to `docs/part-b-strengthening-design.md` (Steps 1-4, which produced the growth-run
result in `pi_level_experiment/RESULTS.md`'s top section: real beats every control under the
clustered test, including `attn_scrambled_sameattr` at p=0.0156).

## Context

Part B's result was never stress-tested against its own scoring machinery. Four gaps were
identified by re-reading the code after that result shipped:

1. `score_chains.py`'s four non-deterministic conditions (`substituted`,
   `attn_scrambled_samechain/_crosschain/_sameattr`) each draw one random partner via
   `DEFAULT_SEED = 42`. Every published p-value for those four contrasts is one realization of
   that draw, never checked for stability under a different seed.
2. Five contrasts are tested against the same `real` sample with no multiple-comparison
   correction. Wilcoxon signed-rank at n=9, one-sided, has a hard floor of p = 1/512 ≈ 0.00195 —
   several reported p-values (0.0039, 0.0156) are close enough to that floor that the choice of
   correction matters.
3. `score_chains.py`'s Phase A/C functions (`delta_mask_from_sigmoid`, `iou_top_k`) are a
   deliberate *port* of `pilot/spatial_semantic_alignment.py`'s `SpatialSemanticAlignment` class
   (comment at `score_chains.py:119-131`), not an import. Nothing asserts the two produce
   identical output — the published numbers come from the port; the Scenario 1-10 suite only
   ever validated the original.
4. The clustered test has only 9 groups (one per prompt) and roughly 70% of all rows are exact
   zeros. Nothing checks whether the "beats every control" headline survives dropping any single
   prompt.

A second pass asked a sharper question: does Phase B (cross-attention) do any work at all in the
headline `real vs shuffled`/`substituted` contrasts, given that those two hold attention fixed
and vary only the delta mask? And does the ~30% real hit rate hide a mechanically meaningful
split (compositional lock correctly producing an empty delta) inside what reads as pure noise?

## Goals

- Determine whether the growth run's headline ("real beats every control under the clustered
  test") is an artifact of one scoring-RNG draw, uncorrected multiple comparisons, or one
  dominant prompt — before spending further GPU/human budget on it.
- Determine whether Phase B's attention term is load-bearing for the headline contrasts, or
  whether a delta-mask-only statistic reproduces it.
- Decompose the disclosed ~30% real hit rate into "genuinely no signal" vs "compositional lock
  correctly suppressed the delta" — the latter is evidence for the metric, not against it.
- Do all of this at zero additional GPU cost, using the manifest/segmentation-cache artifacts
  already generated by the growth run (`pi_level_experiment/artifacts/manifest_combined.json`
  + `artifacts/segmentation_cache/`, both present locally, gitignored).

## Non-goals (tracked separately, need GPU time or human labeling — not attempted here)

- Segmenter diversity (re-running Stage 2 with Grounded-SAM/OWL-ViT instead of CLIPSeg).
- A human-agreement anchor set (ground truth for IoU scores).
- SDXL / second-architecture replication.
- Anything in Part A (metric A's one-shot notebook, sub-chance n=2/n=3 anomaly).
- Porting fixes back to `origin/feature/spatial-semantic-alignment-metric` and re-running
  Scenario 1-10 — deferred until after this validation pass, in case it changes what needs
  porting.

These four remain the actual next tier of work; this design only covers what can be checked for
free against data already on disk.

## Architecture

All of Part C is pure numpy/pandas against existing artifacts. No new GPU stage, no changes to
`generate_chains.py` or `segment_cache.py`.

```
pi_level_experiment/
  score_chains.py          # extended: ablation conditions (Step 6), mask-area columns (Step 7)
  analyze_results.py       # extended: Holm correction (Step 3), leave-one-out (Step 4),
                            #           joint T x top-k sweep (Step 5)
  equivalence_check.py     # new (Step 1): asserts score_chains.py's port matches
                            #           pilot/spatial_semantic_alignment.py bit-for-bit
  rng_sweep.py             # new (Step 2): re-scores across many RNG seeds, reports the
                            #           distribution of each contrast's p-value
  tests/
    test_equivalence_check.py
    test_rng_sweep.py
    test_analyze_results.py   # new: Holm correction, leave-one-out
    test_score_chains.py      # extended: ablation conditions, mask-area columns
```

## Step 1 — Implementation equivalence (the gate)

Before trusting any re-analysis of the growth-run numbers, confirm the numbers came from code
that matches the validated original.

`equivalence_check.py` feeds identical random arrays (a grid of shapes, sparsity levels, and
thresholds/top-k fractions, plus the deterministic hand-built cases already in
`tests/test_score_chains.py`) to both:
- `score_chains.delta_mask_from_sigmoid` vs `SpatialSemanticAlignment.phase_a_delta_mask_from_masks`
- `score_chains.iou_top_k` vs `SpatialSemanticAlignment.phase_c_alignment_score`

and asserts bit-identical (or floating-point-exact via `np.testing.assert_allclose` with a tight
tolerance) output. The one known implementation difference — `score_chains.py` resizes with
`scipy.ndimage.zoom`, the original resizes with `torch.F.interpolate` — is included on purpose:
run one case with mismatched attention/delta shapes to see whether that difference produces a
measurable score difference. Cached attention maps in the manifest already match the delta
mask's resolution in every real chain, so this case is a robustness check, not an expected
divergence.

**Decision rule, pre-registered:** if the two implementations diverge on any same-shape case,
this blocks everything downstream — the growth-run numbers must be re-derived from whichever
implementation is correct before Steps 2-7 mean anything. If they diverge only on the
mismatched-shape resize path, and no real chain ever hits that path, record it as a known,
inert divergence and proceed.

**Acceptance:** equivalence check passes as a pytest test; if it fails, the failure is reported
before any other step's results are treated as final.

## Step 2 — RNG robustness sweep

`rng_sweep.py` re-runs `score_chains.score_chains(manifest, cache_dir, threshold=0.85, seed=s)`
for `s` in a pre-registered range (`range(200)`), and for each of the four RNG-dependent
conditions (`substituted`, `attn_scrambled_samechain`, `attn_scrambled_crosschain`,
`attn_scrambled_sameattr`) recomputes the clustered Wilcoxon p-value at each seed. Reports, per
contrast: median p, IQR, and the fraction of the 200 seeds where p < 0.05.

`real vs shuffled` is excluded from the sweep — it has no RNG dependence (`shuffled` iterates
every wrong step deterministically, no `rng.choice` involved) — confirmed by reading
`score_chains.py:203-211`.

**Decision rule, pre-registered:** a contrast is reported as "robust" only if p < 0.05 in at
least 95% of the 200 seeds. Anything below that is reported as "seed-fragile" with its actual
hit rate stated plainly, and the growth-run's single-seed number is relabeled as one draw, not
a stable result, in RESULTS.md.

**Acceptance:** `rng_sweep.py` runs end-to-end against `manifest_combined.json` and
`segmentation_cache/` in well under a minute (pure numpy scoring, no GPU); a table of the four
contrasts' seed-robustness lands in RESULTS.md.

## Step 3 — Multiple-comparison correction

Add `holm_correction(p_values: Dict[str, float]) -> Dict[str, float]` to `analyze_results.py`:
standard Holm-Bonferroni step-down over the 5 control contrasts' clustered p-values. Apply it to
the growth run's already-published numbers first (0.0039, 0.0039, 0.0039, 0.0195, 0.0156) as a
recomputation of existing data — no rescoring needed — then apply it again to whatever Step 2's
RNG sweep says is the typical (median-seed) p-value per contrast, since the single-seed numbers
being corrected are exactly the ones Step 2 questions the stability of.

**Decision rule, pre-registered:** report both corrected and uncorrected clustered p-values
side by side in RESULTS.md. If a contrast's corrected p exceeds 0.05, the "beats every control"
headline is restated as "beats every control under the uncorrected clustered test; N of 5
contrasts survive Holm correction" — not silently kept as-is.

**Acceptance:** `holm_correction` has a unit test against a known Holm-correction worked example
(independent of this project's data) plus a test applying it to the growth run's actual 5
p-values; RESULTS.md states both corrected and uncorrected numbers.

## Step 4 — Leave-one-prompt-out sensitivity

Add `leave_one_out_check(df) -> Dict[str, dict]` to `analyze_results.py`: for each of the 9
prompts, drop it and recompute the clustered Wilcoxon test on the remaining 8 for every
contrast. Reports, per contrast, the worst-case (maximum) p-value across the 9 leave-one-out
runs and which prompt produced it.

**Decision rule, pre-registered:** a contrast is reported as "not carried by a single prompt" if
it remains significant (p < 0.05) under every one of the 9 leave-one-out runs. If dropping any
one prompt flips significance, name that prompt and report the result as sensitive to it, rather
than reporting only the full-sample p-value.

**Acceptance:** `leave_one_out_check` has a unit test against a small synthetic dataset with a
known single-outlier-prompt case; the full worst-case table lands in RESULTS.md.

## Step 5 — Joint threshold × top-k robustness sweep

`analyze_results.threshold_sweep_curve` already exists (pooled Mann-Whitney only, T only) but
was never run against real data or reported. Extend it to a 2-D grid: `T` over the existing
range (`0.05` to `0.95` step `0.05`) crossed with `threshold_pct` (top-k fraction) over
`{0.05, 0.10, 0.20, 0.30, 0.40}` — 0.20 is the value used throughout and was never itself
calibrated. Report both the pooled and clustered p-value surfaces for `real vs shuffled`
(fully RNG-independent — `shuffled` iterates every wrong step deterministically) at the primary
grid resolution.

**Correction to an earlier draft of this section:** `real vs substituted` is *not*
RNG-independent — `score_chains.py` selects the foreign attribute via `rng.choice`, which is
exactly why Step 2 lists `substituted` among the RNG-dependent conditions. Running its surface
at a single fixed seed (the pre-registered default, 42) would silently understate that
dependence. Report the `substituted` surface at the default seed with that caveat stated
explicitly alongside it, and cross-reference Step 2's seed-robustness finding for `substituted`
rather than treating the surface as deterministic.

**Decision rule, pre-registered:** report the full surface, not just the operating point
(T=0.85, top-k=0.20). A narrow significant region surrounding that single operating point is
reported as a limitation (the frozen constants are doing real work); a broad significant region
is reported as a robustness finding.

**Acceptance:** the surface is computed end-to-end from `manifest_combined.json` +
`segmentation_cache/` (pure numpy, no GPU) and both the table and a plain-language read of its
shape land in RESULTS.md.

## Step 6 — Ablations: is Phase B load-bearing?

**Revised from an earlier draft of this section**, after re-reading `iou_top_k`: a literal
content-free *uniform* attention map always returns exactly 0.0 (the `max == min` degenerate-map
guard), which would make an "`attn_uniform`" condition tautologically zero for every row — not
an empirical finding, just re-deriving the guard. The corrected design adds two **columns**,
not two new pseudo-conditions, to every row already being scored by the existing six conditions
(`real`, `shuffled`, `substituted`, `attn_scrambled_*`):

- `delta_area`: that row's own delta mask, normalized (`delta_mask.mean()`). Because every
  condition already has its own delta mask (`shuffled`'s from the wrong step, `substituted`'s
  from the foreign attribute, `attn_scrambled_*`'s the same as `real`'s), the existing
  pooled/clustered significance tests can simply be re-run with `delta_area` as the score column
  instead of `iou` — no new condition needed to ask "does the delta mask alone separate real
  from shuffled/substituted, with no attention term at all?"
- `iou_random_attn`: IoU of that row's own delta mask against a **genuinely random** (not
  uniform/constant) attention-shaped map, so top-k selects a random k-subset of pixels rather
  than tripping the degenerate-map guard. Re-running the significance tests on this column asks
  "would real still beat shuffled/substituted if attention were replaced by chance-level noise
  with no relationship to the image?" — the correct null baseline, unlike a literal constant map.

**Correctness requirement surfaced while designing this (not yet a bug, caught before
implementing):** the random map for `iou_random_attn` must be drawn from an RNG stream that is
**independent of** `score_chains.py`'s existing `rng = random.Random(seed)`, which
`substituted`/`attn_scrambled_*` already consume via `rng.choice`. Adding a per-row
`rng.randint(...)` draw to seed the ablation map would shift every subsequent `rng.choice` call,
silently changing which foreign attribute and scrambled partner get selected at the *same*
`seed` — invalidating reproducibility of the already-published growth-run numbers. Use a
separate `np.random.RandomState(seed)` for the ablation map instead, so adding this column
changes nothing about the existing conditions' RNG-dependent draws.

**Decision rule, pre-registered:** if `delta_area` alone reproduces the `real vs shuffled` /
`real vs substituted` clustered significance at a comparable effect size, state explicitly that
Phase B's attention term is not shown to add discriminating power beyond the delta mask alone
for those two contrasts, and that the paper's framing needs to lead with Phase A, not Phase B,
for that specific claim. If `iou_random_attn` reproduces the same significance the real `iou`
column achieves, that says the *specific spatial content* of attention isn't shown to matter —
only its sparsity/top-k structure is. If neither ablation reproduces the full metric's
significance, that is evidence Phase B (and its specific content) is load-bearing — report it
as such, not hedge it.

**Acceptance:** both `delta_area` and `iou_random_attn` columns appear for every row in the
scored CSV; a unit test confirms adding them does not change any existing condition's `iou`
value or the RNG-dependent conditions' selected attribute/partner at a fixed seed (the
independent-RNG-stream requirement above, verified not assumed); the re-run significance tests
on both new columns land in RESULTS.md.

## Step 7 — Zero-inflation decomposition

Extend `score_chains.add_row` to also record `curr_mask_area` and `prev_mask_area` (fractions of
image area), alongside the `delta_area` column Step 6 already adds, for every row of every
condition. Add an analysis in `analyze_results.py` that cross-tabs, for the `real` condition's
zero-IoU rows specifically:

- **lock-suppressed**: `delta_area == 0` (attribute already present in `prev`, or absent from
  `curr` too) — this is Phase A's structural guarantee firing correctly, not noise.
- **detected-but-missed**: `delta_area > 0` but `iou == 0` — CLIPSeg found new content, but
  attention's top-k didn't overlap it. This is the case that actually weakens the metric.

**Decision rule, pre-registered:** report the split plainly. A real hit-rate of ~30% with most
of the remaining 70% falling in "lock-suppressed" is a materially different, more favorable
story than the same 30% with most of the rest in "detected-but-missed" — state which one the
growth-run data shows, without rounding either category into the other.

**Acceptance:** the three new columns appear in the scored CSV for every condition; the
lock-suppressed vs detected-but-missed split for `real`'s zero rows is reported as counts and
percentages in RESULTS.md.

## Testing

Every new function above ships with a test against a hand-built manifest/cache, following the
existing pattern in `tests/test_score_chains.py` (no torch/diffusers, `tmp_path` fixtures,
`segment_cache.save_cached_map` to seed synthetic cache entries). `equivalence_check.py` and
`rng_sweep.py` additionally get one test each that runs the real check end-to-end against a tiny
synthetic manifest (not `manifest_combined.json` itself, which is a data run, not a unit test
fixture).

## Risks

- **Step 1 fails.** If the port and the original genuinely diverge on real inputs, every
  post-Step-1 result in this document needs to be recomputed from whichever implementation is
  correct before it means anything. This is the reason Step 1 is first and blocking.
- **RNG sweep (Step 2) is slow.** 200 reseeds × full manifest scoring is still pure numpy; if it
  is not in fact fast, reduce to 50 seeds and say so explicitly rather than silently truncating.
- **Ablation (Step 6) shows Phase B isn't load-bearing.** This is a real risk to the paper's
  current framing (Phase B/attention as the novel mechanism), not just a null result to shrug
  off — see the decision rule above. Report it even though it complicates the pitch.
- **Zero-inflation decomposition (Step 7) shows mostly detected-but-missed, not
  lock-suppressed.** That would mean the ~30% hit rate is mostly a real weakness, not a
  disguised feature of the lock design. Report it as such.
